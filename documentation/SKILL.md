# documentation

负责项目**文档**。

## 最终目标

> 一个新开发者拿到项目后，可以快速运行和理解项目。

## 生成的文档

按需生成以下文档：

```
README.md          项目入口与快速上手
ARCHITECTURE.md    架构说明
API.md             接口文档
DATABASE.md        数据库说明
DEVELOPMENT.md     开发指南
DEPLOYMENT.md      部署指南
CHANGELOG.md       变更记录
FAQ.md             常见问题
```

## 覆盖内容

文档需要覆盖：

- **项目介绍**：背景、目标、核心功能
- **环境要求**：依赖版本、运行时
- **安装**：依赖安装、初始化步骤
- **配置**：配置文件、环境变量说明
- **启动**：如何运行（本地/开发环境）
- **开发**：目录结构、编码约定、如何参与开发
- **测试**：如何运行测试
- **架构**：模块、数据流、技术栈
- **API**：接口、认证、示例
- **数据库**：表结构概览、迁移
- **部署**：构建、发布、环境
- **常见问题**：FAQ
- **故障排查**：常见错误与排查方法

## 编写原则

- **面向新人**：假设读者刚开始接触项目，能照着步骤跑起来。
- **准确可复制**：命令、路径、配置必须与真实项目一致，可被直接执行。
- **与代码同步**：文档反映真实实现，不写臆造内容。
- **适度分层**：README 够用即可，细节放独立文档，避免冗长堆砌。
- **可维护**：结构清晰，便于后续更新。

## 输出

以 README.md 入口 + 按需的独立文档组织，遵循：
- README：项目简介、快速开始、文档导航
- 独立文档：单一主题、结构化的完整说明

## 常识

- 好文档能降低团队上手成本与沟通成本，是项目的"隐性资产"。
- 文档随代码演进，保持同步比一次性写全更重要。
