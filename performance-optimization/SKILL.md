# performance-optimization

负责**性能分析与优化**。

## 最终目标

> 定位性能瓶颈并进行优化，且以数据为凭据衡量效果。

## 覆盖范围

### 前端
- 页面加载、JS、CSS
- 图片、网络请求、渲染、缓存

### 后端
- API 响应时间、CPU、内存、IO
- 并发、线程、数据库查询

### 数据库
- 慢 SQL、索引、查询计划
- N+1、数据量增长

## 核心原则

> 没有数据，不做无依据的性能优化。

先测量，再定位，最后动手；不做无数据的猜测式优化。

## 优化流程

```
发现问题
  ↓
测量（基准数据）
  ↓
定位瓶颈
  ↓
制定方案
  ↓
修改
  ↓
Benchmark（复测）
  ↓
对比（与优化前对比）
```

## 优化要则

- **先测量**：用数据确认瓶颈确实存在，并量化现状。
- **定位瓶颈**：用 profiling / 指标找到真实热点，而非凭感觉。
- **对症下药**：方案针对定位到的瓶颈，不做无关改动。
- **改后复测**：同一基准条件下复测，用数据证明提升。
- **对比记录**：记录优化前后数据，量化收益。

## 常见优化手段

- 前端：资源压缩、懒加载、缓存、CDN、渲染优化、减少请求
- 后端：索引、缓存、异步化、连接池、限流与并发调优
- 数据库：慢 SQL 优化、索引/覆盖索引、查询改写、分区归档

## 输出

ALWAYS 使用以下结构生成性能报告：

```
# 性能分析与优化报告
## 1. 问题描述与指标
## 2. 测量方法与环境（基准数据）
## 3. 瓶颈定位（数据/调用链）
## 4. 优化方案
## 5. 改动说明
## 6. Benchmark 结果（优化前后对比）
## 7. 结论与后续建议
```

## 常识

- 优化要有收益边界：只优化真实瓶颈，避免过度优化。
- 每次优化都要能回答"数据上提升了多少"。
