# ui-design

负责前端**页面与交互**设计。

## 最终目标

> 系统界面应该长什么样、怎么操作：设计到可被 development 直接实现的程度。

## 一、强制输出（不可省略）

1. **页面清单与组件层级**（可对应 product-design 页面）。
2. **每个关键页面的状态设计**（与产品五态对齐）。
3. **交互说明**：点击、提交、校验、反馈文案。
4. **与 API 的数据绑定**（字段来源）。
5. **基础响应式**或目标分辨率说明。

## 二、输入与前置

- 输入：product-design（页面清单、五态、权限矩阵、流程）、api-design（字段与接口）。
- 字段来源、状态、权限均以产品与 API 契约为准，不擅自发明。

## 三、页面清单与组件层级（强制）

- 页面与 product-design 对应：每个页面标注对应产品页面。
- 拆出可复用组件，给出组件树/层级。

```
页面清单：
- 登录页（对应产品：登录）
- 任务列表页（对应产品：任务列表）
  └─ 组件树
     └─ 列表页
         ├─ TaskTable
         │   ├─ Row
         │   └─ RowActions
         ├─ StatusFilter
         └─ CreateDialog
```

| 页面 | 对应产品页面 | 核心组件 |
| ---- | ------------ | -------- |
| 任务列表页 | 任务列表 | TaskTable, StatusFilter, CreateDialog |

## 四、每个关键页面的状态设计（与产品五态对齐）

对每个关键页面，覆盖与 product-design 一致的**五态**（正常/加载/空/错误/无权限），并可选网络异常：

| 状态 | 呈现 | 引导/动作 |
| ---- | ---- | --------- |
| 正常 | 数据完整渲染 | - |
| 加载 | 骨架屏/loading | - |
| 空 | 空态文案 | "去创建第一个任务"按钮 |
| 错误 | 错误提示 | 重试按钮 |
| 无权限 | 无权限提示 | 返回首页 |
| 网络异常（可选） | 断网提示 | 重试 |

- 状态数量与定义必须与 product-design 一致，不冲突。

## 五、交互说明（强制）

对每个页面/组件写清交互：

- **点击**：点击某元素触发什么、目标跳转或弹窗。
- **提交**：表单提交交互、提交中禁用防重复、成功后反馈。
- **校验**：字段何时校验（失焦/提交）、规则、错误文案。
- **反馈文案**：成功/失败/校验的文案，明确具体说明（见空态/错误态规范）。

```
创建任务 Dialog：
- 点击"新建"→ 打开 Dialog（表单：标题、截止日期）。
- 标题失焦校验：为空 → 提示"标题不能为空"。
- 点击"创建"→ 按钮 loading 禁用；成功 → 关闭并 Toast"创建成功"；失败 → 就地显示服务端错误。
```

## 六、与 API 的数据绑定（强制，字段来源）

- 每个页面/组件的每个数据字段标注**API 来源**（接口 + 字段名）。
- 保证 UI 字段名与 api-design 契约一致，杜绝"发明字段"。

```
任务列表页数据绑定：
- 列表项 → GET /api/v1/tasks → Task{ id,title,status,due_date }
- 状态筛选 → query status
- 提交创建 → POST /api/v1/tasks → title, due_date
```

## 七、基础响应式 / 目标分辨率（强制）

- 明确主要使用形态（桌面优先 / 移动优先）与**目标分辨率/断点**，不必全覆盖但要有基准。
- 关键适配点（窄屏下表格变卡片、弹窗宽度、导航折叠）。

```
目标：桌面优先，断点 ≥1280 桌面 / 768–1279 平板 / <768 移动。
移动端：任务列表由表格切换为卡片；顶部导航折叠为抽屉；弹窗全屏。
```

## 八、建议增强

### 设计 token / 组件库选型原则
- 颜色、字体、间距、圆角、阴影用 **design token** 集中定义，全站复用。
- 组件选型：优先成熟组件库（如 MUI/AntD/Chakra）+ 少量定制，减少重复造轮子。
- 少用魔法值，样式来源单一。

### 无障碍最低要求
- **焦点顺序**：键盘可达，Tab 顺序合理，焦点可见。
- **aria**：关键控件（弹窗、下拉、错误提示）有 aria-label/role。
- **对比度**：正文与背景 ≥ 4.5:1，大字号 ≥ 3:1。
- 所有交互元素可用键盘操作。

### 空态与错误态引导文案规范
- **空态**：说明现状 + 给出下一步动作（"暂无任务，点击新建"）。
- **错误态**：说明原因 + 下一步（"加载失败，请重试"），不出现裸报错/技术栈信息。
- 文案用明确动词与友好的语气，避免命令式裸报错。

### 关键动效与性能注意
- **大列表**：虚拟滚动/分页，避免一次性渲染巨量 DOM；加载用骨架屏而非整页 loading。
- **图片**：按需尺寸、懒加载、占位图/骨架，避免大图阻塞首屏。
- **动效**：克制、不阻塞交互，尊重 `prefers-reduced-motion`。

## 九、输出

ALWAYS 使用以下结构生成 UI 设计：

```
# UI 设计
## 1. 设计规范与 token（配色/字体/间距/圆角）
## 2. 组件库选型原则与组件树
## 3. 页面清单（对应 product-design）
## 4. 布局框架（Layout）
## 5. 导航与路由
## 6. 页面设计（每页：结构/组件/交互/数据绑定/各状态）
## 7. 表单与校验设计
## 8. 表格/列表/详情设计
## 9. 弹窗与反馈设计
## 10. 空态/错误态文案规范
## 11. 响应式与目标分辨率
## 12. 无障碍与性能注意
```

## 十一、质量门槛

### 完成判定（全部满足才可进入 development）

- [ ] 页面清单与组件层级已给出，**对应 product-design** 页面
- [ ] **主流程页面状态齐全**（五态与产品对齐）
- [ ] 交互说明可被 **development 直接实现**（点击/提交/校验/反馈明确）
- [ ] 数据绑定明确（字段来源 = API 契约字段）
- [ ] 响应式/目标分辨率已说明
- [ ] 与 api-design 契约无字段冲突

### 不合格信号

- 页面状态缺五态或与产品对不上
- 交互只说"点击可操作"，无明确触发/校验/反馈
- 数据字段来自"估计"而非 API 契约
- 无响应式/分辨率说明
- 空态/错误态无引导文案

## 十二、单页面完整状态与交互示例

```
# 页面设计（示例：任务列表页，对应产品"任务列表"）

## 路由：/tasks；区块：顶部栏 + 侧栏导航 + 内容区。

## 核心组件与数据绑定
| 组件 | 数据来源 |
| TaskTable | GET /api/v1/tasks → items[{id,title,status,due_date}] |
| StatusFilter | query status |
| CreateDialog | 提交到 POST /api/v1/tasks → title,due_date |

## 交互
- 点击"新建任务"→ 打开 CreateDialog。
- 点击筛选"已完成"→ 重新请求 ?status=2，列表刷新。
- Dialog 标题为空点"创建"→ 校验失败，提示"标题不能为空"，不提交。
- 提交成功 → 关闭 Dialog，Toast"创建成功"，刷新列表。
- 提交失败 → Dialog 内显示"保存失败，请重试"。

## 状态覆盖
- 正常：表格显示当前筛选的任务。
- 加载：表格区显示骨架屏。
- 空：显示"暂无任务" + "新建任务"按钮。
- 错误：显示"加载失败" + "重试"按钮。
- 无权限：显示"无访问权限" + 返回首页按钮。

## 响应式
桌面 表格；<768 切换为卡片列表；窄屏弹窗全屏。

## 无障碍
筛选与新建均可键盘；错误提示带 aria-live；正文对比度 ≥ 4.5:1。
```

## 常识

- UI 是用户直接接触的层，友好度直接影响产品成败。
- 先定规范与组件，再铺页面，能保证一致性并减少重复劳动。
- 交互与数据以产品/API 契约为准，设计到 development 可照做，才算完成。
