# ui-design

负责前端**页面与交互**设计。

## 最终目标

> 系统界面应该长什么样、怎么操作。

## 设计内容

- **页面**：完整页面清单，含页面职责与主要信息
- **Layout**：整体布局骨架（导航、侧栏、内容区、页脚）
- **Component**：可复用组件划分与职责
- **Navigation**：导航与页面跳转
- **Form**：表单字段、校验、提交交互
- **Button**：按钮的类型、状态（primary/info/text/danger）、禁用态
- **Dialog**：对话框的启用条件、内容、关闭逻辑
- **Table**：列、排序、筛选、分页、行操作
- **Card**：信息卡片组织方式
- **Loading**：加载反馈形式
- **Empty**：空数据呈现与引导
- **Error**：错误信息呈现与重试
- **Responsive**：不同屏幕尺寸的适配

## 页面状态设计

每个页面不仅设计正常状态，还必须覆盖：

```
正常状态      数据完整可用时的呈现
加载状态      数据获取中的反馈（骨架屏/loading）
空数据状态    无数据时的呈现与引导
错误状态      请求失败的呈现与重试
无权限状态    无访问权限时的呈现
网络异常状态  断网的提示与处理
```

## 设计原则

- **一致性**：组件风格、间距、配色、交互反馈全站统一。
- **可访问性**：键盘可用、对比度、语义化，方便所有用户。
- **以产品设计为准**：交互实现须与 product-design 的用户/业务流程一致。
- **状态完备**：宁可多设计边界状态，也不要让页面在异常时"裸奔"。

## 输出

ALWAYS 使用以下结构生成 UI 设计：

```
# UI 设计
## 1. 设计规范（配色、字体、间距、圆角、组件风格）
## 2. 布局框架（Layout 结构）
## 3. 组件库清单（可复用组件及状态）
## 4. 页面设计（每页：结构、核心组件、交互、各状态的呈现）
## 5. 导航与路由
## 6. 表单与校验设计
## 7. 表格/列表/详情设计
## 8. 弹窗/反馈设计（Dialog、Toast、Error）
## 9. 响应式适配方案
## 10. 无障碍与状态完备性检查
```

## 页面设计模板

```
### 页面：<页面名>
- 层级与路由
- 结构（顶部/Sidebar/内容区）
- 核心组件与数据来源
- 交互说明
- 状态覆盖：正常 / 加载 / 空 / 错误 / 无权限 / 网络异常
```

## 常识

- UI 是用户直接接触的层，界面的友好度直接影响产品成败。
- 先定规范与组件，再铺页面，能保证一致性并减少重复劳动。
